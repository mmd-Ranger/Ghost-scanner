## معرفی

این ابزار (Ghost Scanner) برای ارزیابی پایداری و سرعت واقعی دامنه‌هایی طراحی شده که به‌عنوان **Host Header** (در کانفیگ‌های VLESS + TCP + HTTP Header Obfuscation) یا به‌عنوان **SNI** (در کانفیگ‌های مبتنی بر Reality) مورد استفاده قرار می‌گیرند.

انتخاب یک دامنه‌ی مناسب برای camouflage تأثیر مستقیمی بر پایداری و سرعت اتصال دارد. دامنه‌ای که در یک بازه‌ی زمانی یا از طریق یک اپراتور خاص عملکرد مطلوبی دارد، ممکن است در شرایط دیگر کاملاً غیرقابل‌استفاده باشد. اکثر ابزارهای مشابه صرفاً یک Ping ساده به دامنه ارسال می‌کنند که معیار قابل‌اعتمادی برای عملکرد واقعی تونل نیست.

این ابزار فرآیند را به‌صورت زیر انجام می‌دهد:

- برای هر دامنه، یک **تونل واقعی Xray** ایجاد می‌کند
- چندین دور آزمایش اتصال واقعی از طریق همان تونل انجام می‌دهد
- یک آزمایش throughput واقعی (نه صرفاً تأخیر) نیز اجرا می‌کند
- نتیجه را با برچسب مشخص (پایدار و سریع / نسبتاً پایدار / ناپایدار / غیرفعال) گزارش می‌دهد
- در پایان، فهرستی مرتب‌شده از بهترین گزینه‌ها ارائه می‌دهد

## کاربرد دامنه‌های یافت‌شده

دامنه‌هایی که در نتیجه‌ی اسکن با وضعیت «پایدار و سریع» مشخص می‌شوند، قابل استفاده در موارد زیر هستند:

1. تنظیمات `network: tcp` و `header: http` در کانفیگ‌های VLESS، یعنی همان **Host Header** (obfuscation مبتنی بر هدر HTTP)
2. کانفیگ‌های مبتنی بر **Reality** یا سایر پروتکل‌های TLS-based، یعنی فیلد **SNI** که برای camouflage استفاده می‌شود

به‌طور خلاصه، هر دامنه‌ای که در این ابزار به‌عنوان گزینه‌ی پایدار شناسایی شود، می‌تواند در فیلد مربوطه (Host یا SNI) در کانفیگ نهایی جایگزین شود.

## پیش‌نیازها

- دسترسی ترمینال روی Termux (اندروید) یا هر توزیع Linux
- ابزارهای `bash`, `curl`, `unzip`, `python3` (در صورت نبودن، اسکریپت به‌صورت خودکار نصب آن‌ها را انجام می‌دهد)
- یک کانفیگ VLESS معتبر، شامل آدرس سرور، پورت و UUID، با تنظیمات TCP + HTTP Header Obfuscation

### نکات مهم پیش از اجرا

برای دریافت نتایج معتبر و قابل‌استناد، رعایت موارد زیر ضروری است:

1. **این ابزار باید مستقیماً روی Termux یا ترمینال یک کامپیوتر نصب و اجرا شود.** استفاده از محیط‌های واسط یا شبیه‌سازی‌شده نتایج را غیرقابل‌اعتماد می‌کند.
2. **پیش از شروع اسکن، هرگونه VPN یا تونل فعال باید غیرفعال شود.** وجود یک اتصال VPN فعال، مسیر واقعی ترافیک را تغییر داده و نتایج اسکن را نامعتبر می‌کند.
3. **اتصال اینترنت باید از طریق همان اپراتور یا شبکه‌ای برقرار باشد که کانفیگ نهایی قرار است روی آن استفاده شود** (برای مثال، همان سیم‌کارت یا همان کن‌نت موردنظر). نتیجه‌ی یک دامنه می‌تواند بین اپراتورها و شبکه‌های مختلف کاملاً متفاوت باشد؛ بنابراین اسکن باید در همان شرایط شبکه‌ای انجام شود که کانفیگ نهایی در آن استفاده خواهد شد.

## نصب و اجرا

بدون نیاز به `git` — با یک دستور `curl` فایل را دریافت و اجرا کنید:

```bash
curl -L -o ghost_scanner.sh https://raw.githubusercontent.com/mmd-Ranger/Ghost-scanner/main/ghost_scanner.sh
bash ghost_scanner.sh
```

در صورت نبود `curl`، از `wget` نیز می‌توان استفاده کرد:

```bash
wget -O ghost_scanner.sh https://raw.githubusercontent.com/mmd-Ranger/Ghost-scanner/main/ghost_scanner.sh
bash ghost_scanner.sh
```

فایل‌های کمکی (`sni_scanner.py`, `domains.txt`, `server_config.conf`) در اولین اجرا به‌صورت خودکار در کنار اسکریپت اصلی ساخته می‌شوند. دریافت هیچ فایل دیگری لازم نیست.

## راهنمای استفاده

پس از اجرای دستور `bash ghost_scanner.sh`، منوی اصلی نمایش داده می‌شود:

```
==================================================
        VLESS SNI / Domain Scanner
==================================================
  Xray status:   Not installed
  Config status: Not set
  Domains file:  15 domain(s)

1) Xray Setup
2) Server Config
3) Domains
4) Run Scan
5) Exit
```

### گام ۱ — نصب Xray
گزینه‌ی ۱ را انتخاب کنید. پلتفرم و معماری سیستم به‌صورت خودکار شناسایی و نسخه‌ی مناسب از [Xray-core](https://github.com/XTLS/Xray-core) دریافت و نصب می‌شود.

### گام ۲ — وارد کردن اطلاعات سرور
گزینه‌ی ۲ سپس «Edit config» را انتخاب کرده و آدرس، پورت و UUID سرور را وارد کنید. در صورت نامعتبر بودن فرمت (مانند UUID نادرست یا پورت خارج از محدوده‌ی مجاز)، اطلاعات ذخیره نخواهد شد. پس از ذخیره‌سازی موفق، امکان آزمایش با یک اتصال واقعی وجود دارد.

### گام ۳ — تنظیم فهرست دامنه‌ها
گزینه‌ی ۳ سپس «Edit domains» فهرست دامنه‌ها را با ویرایشگر nano باز می‌کند. هر دامنه در یک خط جداگانه قرار می‌گیرد. در صورت نیاز، فهرست کامل را می‌توان از طریق «Delete all domains» پاک و از نو تنظیم کرد.

### گام ۴ — اجرای اسکن
پیش از انتخاب گزینه‌ی ۴، اطمینان حاصل کنید که:
- هرگونه VPN یا تونل فعال خاموش است
- اتصال اینترنت از طریق اپراتور/شبکه‌ی موردنظر برقرار است

سپس گزینه‌ی ۴ را انتخاب کنید. هر دامنه از طریق یک تونل واقعی آزمایش شده و در پایان، گزارشی مرتب‌شده به همراه بهترین گزینه‌ها نمایش داده می‌شود:

```
🏆 BEST OPTIONS (stable & fast):
   - config.office.com  (305.9ms, 1419.8KB/s)
   - login.live.com  (528.5ms, 678.5KB/s)
```

## نحوه‌ی عملکرد فنی

برای هر دامنه‌ی موجود در فهرست:

1. یک کانفیگ موقت Xray ساخته می‌شود که از آدرس، پورت و UUID واردشده استفاده می‌کند و تنها Host Header آن تغییر می‌کند
2. سپس Xray به‌صورت واقعی اجرا شده و یک پراکسی SOCKS روی `127.0.0.1:10808` راه‌اندازی می‌شود
3. از طریق همین تونل، سه دور آزمایش اتصال (به آدرس `cp.cloudflare.com/generate_204`) انجام می‌شود
4. یک آزمایش throughput واقعی (دریافت ۲ مگابایت داده از `speed.cloudflare.com`) نیز اجرا می‌شود
5. بر اساس نرخ موفقیت و سرعت، برچسب نهایی هر دامنه تعیین می‌شود
6. برای هر دامنه یک محدودیت زمانی (Timeout) در نظر گرفته شده تا در صورت گیر کردن یک دامنه، کل فرآیند اسکن متوقف نشود

## حذف کامل (Uninstall)

برای حذف کامل Ghost Scanner و تمام فایل‌های مرتبط با آن، دستورات زیر را اجرا کنید:

```bash
# حذف باینری Xray
rm -rf ~/xray-core

# حذف فایل کانفیگ موقت تست
rm -f ~/xray_test_config.json

# حذف خود اسکریپت و فایل‌های کمکی (در مسیری که اسکریپت را اجرا کرده‌اید)
rm -f ghost_scanner.sh sni_scanner.py domains.txt server_config.conf .config_validated
```

اگر مسیر اجرای اسکریپت پوشه‌ی جداگانه‌ای بوده (مثلاً `~/ghost-scanner`)، می‌توان کل پوشه را یک‌جا حذف کرد:

```bash
rm -rf ~/ghost-scanner
```
